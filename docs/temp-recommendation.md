# 추천 온도 알고리즘

> 편안타(MotionCare) · 스키마 v0.3.3 기준 · 코드: `shared/src/main/java/com/carfortable/shared/TempRecommendation.kt`

## 1. 목적

한 차에 탄 사람들은 원하는 온도가 서로 달라요. 그런데 뒷좌석에는 전용 온도 구역이 없어서, 차 안 전체를 **한 온도**로 맞춰야 해요.

편안타는 모두의 희망 온도를 반영하되, **멀미를 많이 느끼는 사람의 의견을 더 크게** 반영해서 추천 온도를 정해요. 멀미가 심한 사람에게 온도는 편안함에 더 큰 영향을 주기 때문이에요.

## 2. 한눈에 보기

1. 차량 앱이 **30분마다** 탑승자별 **가중치**를 다시 정해요.
2. 희망 온도의 **가중평균**으로 추천 온도를 계산해요.
3. 지금 온도와 다르면 차량 화면에서 **운전자에게 물어봐요**.
4. 운전자가 [적용]을 누르면 운전석·조수석 두 구역에 같은 온도를 적용해요.

## 3. 입력 값

| 값 | 어디서 | 설명 |
|---|---|---|
| 희망 온도 | `passengers/{seat}.desiredTemp` | 18~26℃, 처음 설정과 메인 화면에서 입력 |
| 멀미 민감도 | `passengers/{seat}.sensitivity` | 없음 / 낮음 / 보통 / 높음 |
| 추가 항목 | `passengers/{seat}.sicknessTriggers` | "영상 시청 시 멀미가 잘 나요", "차량 이동 중 화면 보기 불편해요" |
| 최근 불편 요청 | `requests` (최근 30분) | 메스꺼워요 / 추워요 / 더워요 / 쉬고 싶어요 |
| 지금 실내 온도 | 차량 공조 (Vehicle SDK) | 운전석·조수석 실제 온도 |

희망 온도를 아직 정하지 않은 사람은 계산에서 빠져요.

## 4. 가중치

가중치는 **"이 사람의 의견을 얼마나 크게 반영할지"**를 나타내는 숫자예요. 아래 항목을 모두 더해요.

| 항목 | 더하는 값 |
|---|---|
| 멀미 민감도 (기본) | 없음 **1** / 낮음 **1.5** / 보통 **2** / 높음 **3** (미입력 1) |
| 추가 항목 | 1개당 **+0.25** |
| 최근 30분 "메스꺼워요" | 1번당 **+2** (최대 +4) |
| 최근 30분 "잠깐 쉬고 싶어요" | **+1** |

- 처음에는 **멀미 민감도**로 정해져요.
- 이동 중에 **실제로 메스꺼움을 알린 사람**은 가중치가 커져요.
- 30분이 지나면 그 요청은 계산에서 빠져서 가중치가 다시 원래대로 돌아와요. 이게 **"30분마다 가중치가 바뀐다"**는 뜻이에요.

**온도 요청 반영**: 최근 30분 안에 "너무 추워요"를 보냈다면 그 사람의 희망 온도를 **+1℃**, "너무 더워요"면 **−1℃**로 보고 계산해요. 여러 번 보냈으면 가장 마지막 요청만 반영해요.

## 5. 계산 방법: 가중평균

```
추천 온도 = (각자 희망 온도 × 가중치)의 합 ÷ 가중치의 합
```

- 가중치가 큰 사람일수록 결과가 그 사람의 희망 온도 쪽으로 가까워져요.
- 모두 가중치가 같으면 그냥 평균과 같아요.

## 6. 안전장치

| 규칙 | 이유 |
|---|---|
| 0.5℃ 단위로 반올림 | 차량 공조 설정 단위에 맞추기 |
| **18~26℃** 안에서만 추천 | 너무 춥거나 더운 설정 방지 (차량 공조 범위는 16~30℃) |
| 한 번에 **최대 2℃까지만** 변경 | 갑자기 확 추워지거나 더워지지 않게 |
| 지금 온도와 **0.5℃ 미만** 차이면 제안하지 않음 | 운전자에게 의미 없는 확인 요청을 보내지 않게 |

## 7. 언제 계산하나

| 시점 | 설명 |
|---|---|
| **정기** | 30분마다 |
| **즉시** | 탑승자가 처음 설정을 제출했을 때 (탑승 직후 30분을 기다리지 않게) |
| **즉시** | "메스꺼워요" 요청이 들어왔을 때 (급한 상황) |

## 8. 운전자 확인과 적용

| 상황 | 차량 앱이 기록하는 값 | 화면 |
|---|---|---|
| 새 추천 온도가 나옴 | `medianTemp` = 추천 온도, `tempStatus: "pending"` | 차량: [적용] / [나중에] · 폰: "운전자 확인 대기" |
| 운전자 [적용] | 두 구역 온도 적용 → `tempStatus: "applied"` | 폰: "적용됨" |
| 운전자 [나중에] | 공조 그대로 → `tempStatus: "driver_set"` | 폰: "운전자가 정한 온도 유지" (다음 회차에 다시 계산) |
| 차이가 작음 | `reviewedAt`, `nextReviewAt`만 갱신 | 변화 없음 |

함께 기록하는 값:

- `voteCount`: 계산에 참여한 사람 수
- `leadSeat`: 가중치가 가장 큰 좌석 (혼자 1위일 때만). 폰에 "멀미를 가장 많이 느끼는 현아 님을 더 고려했어요"로 보여요.
- `reviewedAt`, `nextReviewAt`: 마지막 계산 시각, 다음 계산 시각. 폰에 "다음 조정 11:30"으로 보여요.

## 9. 예시

**예시 1: 멀미가 심한 사람 쪽으로**

| 탑승자 | 멀미 | 가중치 | 희망 온도 |
|---|---|---|---|
| 현아 | 높음 | 3 | 22℃ |
| 윤지 | 없음 | 1 | 25℃ |
| 성윤 | 없음 | 1 | 26℃ |

(22×3 + 25×1 + 26×1) ÷ 5 = 23.4 → **23.5℃**
그냥 평균(24.3℃)보다 현아가 원하는 온도 쪽으로 가까워졌어요.

**예시 2: 방금 메스꺼움을 알린 경우**

| 탑승자 | 가중치 | 희망 온도 |
|---|---|---|
| 현아 | 보통 2 + 메스꺼워요 2 = **4** | 20℃ |
| 윤지 | 높음 **3** | 25℃ |

(20×4 + 25×3) ÷ 7 = 22.1 → **22℃**

30분이 지나 현아의 가중치가 2로 돌아오면: (20×2 + 25×3) ÷ 5 = **23℃**

**예시 3: 한 번에 최대 2℃**

지금 실내 26℃, 계산 결과 20℃ → 이번 회차 추천은 **24℃**. 30분 뒤 다시 계산해서 22℃, 그다음 20℃로 천천히 내려가요.

**예시 4: 추워요 요청**

현아(희망 22℃)가 10분 전에 "너무 추워요"를 보냄 → 이번 회차에는 **23℃**로 보고 계산해요.

## 10. 조정 가능한 값

모든 숫자는 코드의 `RecommendRule` 한 곳에 모여 있어서, 시연하면서 쉽게 바꿀 수 있어요.

| 이름 | 지금 값 | 의미 |
|---|---|---|
| `REVIEW_INTERVAL_MS` | 30분 | 정기 계산 주기 |
| `WINDOW_MS` | 30분 | 최근 요청으로 보는 기간 |
| `BASE_WEIGHT` | 1 / 1.5 / 2 / 3 | 민감도별 기본 가중치 |
| `TRIGGER_BOOST` | 0.25 | 추가 항목 1개당 |
| `NAUSEA_BOOST`, `NAUSEA_BOOST_MAX` | 2, 4 | 메스꺼워요 1번당, 최대 |
| `REST_BOOST` | 1 | 쉬고 싶어요 |
| `TEMP_NUDGE` | 1℃ | 추워요/더워요 반영 폭 |
| `MIN_CHANGE` | 0.5℃ | 이보다 작은 차이는 제안 안 함 |
| `MAX_STEP` | 2℃ | 한 번에 바꾸는 최대 폭 |

## 11. 역할 나눔

| 누가 | 하는 일 |
|---|---|
| 동승자 폰 (웹) | 희망 온도·민감도 입력, 불편 요청 보내기, 결과 표시 (**계산하지 않음**) |
| 차량 앱 | 30분마다 + 즉시 조건에서 계산, 결과 기록, 운전자 확인 후 공조 적용 |
| 운전자 | 추천 온도 [적용] / [나중에] |

계산을 차량 앱 한 곳에서만 하기 때문에, 폰 여러 대가 서로 다른 값을 덮어쓰는 문제가 없고, 보안 규칙에서도 "공조 상태는 차량만 쓴다"는 원칙을 지킬 수 있어요.

## 12. 한계와 다음 단계

- 가중치 숫자는 경험적으로 정한 초안이에요. 실제 사용 테스트로 조정이 필요해요.
- 희망 풍량(`fanPreference`)과 직접 바람 민감도(`avoidDirectWind`)는 지금은 저장만 하고, 이후 가중치나 풍량 제안에 활용할 예정이에요.
- 멀미 완화 효과에는 개인차가 있어요. 이 알고리즘은 "편안함을 돕는 보조 기능"이에요.

## 13. 테스트

`./gradlew :shared:test`로 9가지 상황을 확인해요: 같은 가중치, 멀미 큰 사람 쪽 반영, 메스꺼워요 가중치 증가, 30분 지난 요청 무시, 최대 2℃, 작은 차이 제안 안 함, 추워요 반영, 희망 온도 없음, 18~26℃ 제한.
