# 시각 케어 (시각적 멀미 완화)

> 차 안에서 화면을 보면 눈은 "멈춰 있다", 몸은 "움직인다"고 느껴서 멀미가 나요.
> 화면 가장자리에 **차의 움직임을 보여주는 안내**를 겹쳐서 그 차이를 줄여요.

## 플랫폼별 범위

| 플랫폼 | 어디에 보이나 | 움직임 출처 | 담당 | 상태 |
|---|---|---|---|---|
| 웹 (iOS·Android) | 우리 웹앱 화면 + 앱 안 영상 플레이어 | 폰 센서 (DeviceMotion) | B | `feature/web-motion-cue` |
| Android | 다른 앱 위 (오버레이) | 폰 센서 | 미정 | 예정 |
| 차량 | 차량 앱 화면 | 차량 SDK (가속도·조향) | A와 협의 | 예정 |

iOS는 다른 앱 위에 띄울 수 없고, 아이폰 기본 "차량 동작 신호"는 시스템 설정이라 자동으로 켤 수 없어요. 그래서 **우리 앱 안에서만** 보여요.

## 세 가지 안내 방식 (`visualMode`)

몸이 쏠리는 방향으로 안내가 움직여요.

| 방식 | 모양 | 좌회전할 때 | 출발할 때 |
|---|---|---|---|
| `dot` 움직이는 점 | 양쪽 가장자리 점 두 줄 | 점이 오른쪽으로 | 점이 아래로 |
| `horizon` 수평선 | 양쪽 가장자리 짧은 선 (가운데는 비움) | 선이 왼쪽 아래로 기울어요 | 선이 아래로 |
| `minimal` 최소 시각 신호 | 가장자리 빛 | 오른쪽 가장자리가 빛나요 | 아래 가장자리가 빛나요 |

`visualIntensity`(약하게 30 / 보통 60 / 강하게 90)는 안내의 크기와 진하기를 정해요.

## 움직임 계산 (`web/src/lib/motion.ts`)

1. 센서 값(`accelerationIncludingGravity`, `acceleration`)을 화면 방향 기준으로 바꿔요. 가로 화면도 지원해요.
2. 느린 필터로 **중력 방향**을 구해서 수평면을 찾아요.
3. 폰을 세워 들든 눕혀 들든 같은 결과가 나오도록 **차량 기준 좌우·앞뒤 가속도**로 바꿔요.
   - 앞쪽 = (화면 위쪽 − 화면 바깥쪽)을 수평으로 눕힌 방향
4. 0.25초 평활 + 0.12 m/s² 이하 무시 (손떨림·노면 진동)
5. 일부 iOS는 부호가 반대라서, 중력 방향을 보고 자동으로 맞춰요.

| 상수 | 값 | 뜻 |
|---|---|---|
| `ACCEL_TAU` | 0.25초 | 가속도 평활 |
| `DEAD_ZONE` | 0.12 m/s² | 이보다 작으면 0 |
| `PX_PER_ACCEL` | 9px | 1 m/s²당 이동 |
| `MAX_SHIFT` | 20px | 최대 이동 |
| `ROLL_PER_ACCEL` | 0.05 rad | 수평선 기울기 |

## 웹 동작

- `MotionCueProvider`(세션 화면 전체를 감쌈): 내 `visualMode`가 켜져 있으면 화면 전체 위에 캔버스를 겹쳐요. 터치는 막지 않아요.
- **iOS 권한**: 움직임 센서는 버튼을 눌러야 허용돼요. "이대로 계속하기"를 누를 때 물어보고, 새로고침 뒤에는 오른쪽 아래 "시각 케어 켜기" 버튼이 떠요.
- **센서가 없으면**(PC, 거부, 1.5초 안에 값이 안 옴) 데모 움직임으로 바꿔요.
- **HTTPS 주소에서만** 센서가 동작해요. 로컬 `http://192.168…`로 폰 테스트하면 데모로 보여요.

## 화면

| 경로 | 내용 |
|---|---|
| `/s/:sid/care` | 방식·강도 고르기 + **실시간 미리보기** |
| `/s/:sid/home` | 켜져 있으면 화면 전체 안내 + "영상 보며 시각 케어" 카드 |
| `/s/:sid/watch` | 앱 안 영상 플레이어. 내 폰의 영상을 고르거나 `VITE_DEMO_VIDEO_URL` 사용. "크게 보기"는 앱 안 전체 화면이라 안내가 가려지지 않아요. 잠시 멈추기, **데모 움직임 (시연용)** 전환 |

시연 팁: 차가 서 있을 때는 `/watch`에서 "데모 (시연용)"를 고르거나 주소 끝에 `?demo`를 붙이세요.
